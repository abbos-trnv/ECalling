# V0-03: сквозной mock-процесс — 2026-11-06

Реализованы канонические схемы, MockASR/MockLLM, версионированный JSON-чек-лист,
детерминированный scorer и валидация evidence. Миграция 0003 добавляет снимки
настроек в processing_runs и immutable transcripts/analysis_runs. Worker
атомарно публикует оба результата и completed только с действующей арендой.

API умеет запускать mock для ранее загруженной записи, читать результат,
историю и старые версии. Список выбирает один последний run без дублей.
UI содержит явный баннер MOCK, транскрипт, категории, критерии, coverage,
providers/models, переключение версий и переход исходного плеера по времени.

Подтверждено:

- Docker build api/web — exit 0; TypeScript и Vite — exit 0.
- Все 35 тестов внутри Docker с PostgreSQL и ffmpeg — passed, exit 0.
- 15 unit-тестов схем, scorer и API прошли отдельно на Windows (CPython 3.13.7).
- Проверены unknown/N/A, score=70 для отдельной синтетической pass/fail-фикстуры,
  null при отсутствии оценённых критериев, role/evidence validation, невозможность
  передать score/ID/is_mock в AnalysisCandidate, полное множество критериев.
- Невалидные evidence отклоняются без частичной публикации результатов.
- При ошибке проверки сохраняется stage=validate, а не сбрасывается на preprocess.
- Повторное нажатие retry для активного run не создаёт параллельную заявку;
  повторная обработка завершённого результата создаёт новую версию. Старые
  payload сохранены и доступны по run_id, UPDATE запрещён триггером.
- Старый lease-token не может публиковать; двойная публикация не создаёт дублей.
- В браузере для собственного demo-upload.wav создан mock-результат, повторён
  запуск и открыта предыдущая mock-версия. Переход по последнему сегменту дал
  currentTime=1.666 при duration=2, без ошибки плеера.
- Для двух ранее загруженных записей Ромашки, связанных с Аббосом и Алишером,
  созданы новые mock-runs. Оба completed, исходные аудио и employee_id сохранены.
- Windows PowerShell smoke проверил 3 опубликованных результата, run IDs,
  mock-флаги, evidence IDs, API, UI proxy, PostgreSQL и Range/206.

Текущий mock не определяет роли и не распознаёт содержимое аудио: все пять
критериев неизвестны, score=null и coverage=0. Это намеренное поведение.
Никакие записи не отправлялись внешним ASR/LLM, seed повторно не запускался.
