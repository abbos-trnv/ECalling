# ADR 0004: сквозной mock-процесс — V0-03

Новые записи получают pipeline_profile=mock и снимок настроек провайдеров и
scorecard при создании processing_run. Старые runs миграцией остаются preprocess:
успешная проверка аудио не подменяется новым результатом автоматически.

MockASR выдаёт один фиксированный вымышленный сценарий и условные интервалы,
масштабированные по длительности записи. Он не слушает и не распознаёт аудио.
MockLLM возвращает фиксированные категории и кандидаты критериев. Исходное
аудио обрабатывается только локальным ffmpeg для проверки, никуда не отправляется.
В БД, API и UI сохраняются is_mock, provider, model, schema/prompt/scorecard versions.
Mock-результаты явно предупреждают, что не описывают запись и сотрудника.

Роли говорящих в mock-транскрипте — unknown; diarization_available=false.
При неизвестной роли менеджера pass/fail нормализуется в unknown. Не создаём
вымышленную оценку сотрудника: для текущего mock score=null, coverage=0.
Работоспособность формулы для известных ролей и pass/fail/N/A проверена отдельно
на синтетических unit-фикстурах (например, 70 из 100). Скоринг — чистая функция,
не LLM: unknown/N/A не являются провалом, N/A исключается и из coverage denominator.

Схемы и scorer находятся в apps/core, провайдеры — apps/ai_adapters. Кандидат
повторно валидируется; проверяются enum, лишние поля, точное множество критериев
и все evidence_segment_ids. Несуществующие ссылки приводят к INVALID_ANALYSIS,
без публикации частичного транскрипта. LLM не определяет ID, is_mock и score.
Транскрипт проверяет интервалы, уникальные IDs и отсутствие неподтверждённых ролей.

Миграция 0003 добавляет transcripts и analysis_runs: уникальный run_id,
составной FK analysis(transcript_id,run_id), JSONB payload и snapshot scorecard.
Триггеры запрещают UPDATE опубликованных результатов. Удаление при будущем
удалении звонка не запрещено. Публикация обоих результатов и completed статусов
происходит одной транзакцией с действующим lease token. Повторный/stale worker
не публикует результат. Stage проходит preprocess/transcribe/analyze/validate/publish.

API:
- POST /companies/{company_id}/calls/{call_id}/retry создаёт новый mock-run для
  awaiting_analysis/failed/completed. При уже queued/processing возвращает
  текущий run (повторное нажатие не создаёт параллельных заявок).
- GET /.../transcript и /.../analysis возвращают результат последнего run;
  409 если он ещё не опубликован. Необязательный run_id позволяет открыть
  старую опубликованную версию, строго внутри того же call/company.
- GET /.../runs возвращает до 50 последних запусков.
- Список звонков выбирает один последний run через LATERAL, без дублей.
- /system: pipeline_available=true, real_inference_available=false.

UI показывает исходный плеер, вымышленный транскрипт, категории, критерии,
оценку/coverage, metadata и историю. Таймкод или evidence переводит исходный
плеер к условному времени; предупреждение прямо говорит, что реплики и таймкоды
не соответствуют содержимому аудио. Смена компании/run отменяет старые запросы.

Настоящие ASR/LLM, KPI dashboard, diarization, production auth и удаление звонков
остаются следующими задачами. Mock не подтверждает качество моделей и не должен
использоваться для оценки сотрудников.
