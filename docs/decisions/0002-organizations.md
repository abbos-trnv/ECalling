# ADR 0002: компании и сотрудники — V0-01

Alembic управляет схемой PostgreSQL. SQLAlchemy используется для миграций,
без ORM: прикладные запросы остаются параметризованным SQL через psycopg.
Миграции выполняются отдельным одноразовым Compose-сервисом migrate до старта
API, а не обработчиком старта API. Seed запускается явно и не меняет существующие имена.

Таблицы companies и employees содержат UUID, имена и created_at с timezone.
Сотрудник обязательно принадлежит компании (FK + индекс). Имена непустые, до
200 символов, не обязаны быть уникальными. Удаление компании с сотрудниками
возвращает 409; каскадного удаления нет.

Контракт /api/v1/companies и вложенных /{company_id}/employees:
GET — массив с limit (1–100, default 100), offset (>=0) и стабильной сортировкой;
POST — создание, 201; PUT /{id} — переименование, 200;
DELETE /{id} — 204, 404 если ресурс не найден. Чужой employee в пути другой
компании также даёт 404. UUID и входные поля валидирует Pydantic; лишние
поля запрещены. Это локальное демо, не аутентификация и не tenant security.

Ошибки предметной области пока используют стандартный FastAPI detail.
Единый envelope ошибок из черновика спецификации откладывается до upload/jobs.

Frontend очищает данные сотрудников при смене компании, отменяет старые запросы
и не отображает данные, полученные для другой компании. Создание и редактирование
привязаны к компании, выбранной в момент запроса. Во время записи переключение
блокируется. Пагинация доступна в API; UI загружает компании страницами,
а сотрудников показывает по 10 на страницу. Транзакции записей завершаются
до отправки HTTP-ответа (FastAPI function scope), чтобы не подтверждать
неуспешное сохранение.
